All user-facing workflow operations are exposed as free functions under `zart::` (Rust), `zart.*` (Python), and `Zart.*` (TypeScript / Effect). There is no `ctx` to thread through your code — each runtime makes the current execution context available automatically.

## Step Execution

### `require`

Execute a step and fail the execution on any non-`Ok` outcome. This is the **default path** — use it when a step's failure means the whole workflow cannot proceed.

<Tabs syncKey="sdk">
<TabItem label="Rust">

```rust
pub async fn require<S>(s: S) -> Result<S::Output, TaskError>
where
    S: ZartStep + Send,
    S::Error: std::error::Error + Send + Sync + 'static,
```

```rust
let inventory = reserve_inventory(order_id.clone()).await?;
```

</TabItem>
<TabItem label="Python">

```python
# Direct await uses require() semantics; zart.require(...) is the explicit equivalent
inventory = await reserve_inventory(order_id)
```

</TabItem>
<TabItem label="TypeScript">

```ts
// Direct yield* uses require() semantics; Zart.require(...) is the explicit equivalent
const inventory = yield* reserveInventory(orderId);
```

</TabItem>
</Tabs>

Both `BusinessErr` and `ZartErr` result in `TaskError::StepFailed` (or `ZartStepFailedError` / `StepFailedError`), preserving the step name for `on_failure` / `onFailure` inspection.

### `step` / `Zart.outcome`

Execute a step and inspect the three-way [`StepOutcome`](/docs/api/error-types/#stepoutcome). Use this when the handler body genuinely needs to branch on a specific step's business error.

<Tabs syncKey="sdk">
<TabItem label="Rust">

```rust
match zart::step(check_balance(account_id.clone())).await? {
    StepOutcome::Ok(b) => { /* ... */ }
    StepOutcome::BusinessErr(PaymentError::InsufficientFunds { balance, needed }) => { /* ... */ }
    StepOutcome::BusinessErr(PaymentError::CardDeclined { reason }) => { /* ... */ }
    StepOutcome::ZartErr(e) => return Err(e.into()),
}
```

The outer `?` propagates control-flow signals (`Scheduled`, `StepExecuted`) — never matched by user code.

</TabItem>
<TabItem label="Python">

```python
outcome = await zart.step(check_balance(account_id))
if outcome.is_ok:
    balance = outcome.value
elif outcome.is_business_err:
    print("Business error:", outcome.error)
else:
    raise outcome.error
```

</TabItem>
<TabItem label="TypeScript">

```ts
const balanceOutcome = yield* Zart.outcome(checkBalance(accountId));
if (balanceOutcome._tag === "ok") {
  const balance = balanceOutcome.value;
} else if (balanceOutcome._tag === "business_err") {
  console.log("Business error:", balanceOutcome.message);
} else {
  return yield* Effect.fail(balanceOutcome.error);
}
```

</TabItem>
</Tabs>

### `step_or` / `Zart.stepOr`

Execute a step, returning a default value on any failure (business or framework). Use only when the specific failure reason does not matter.

<Tabs syncKey="sdk">
<TabItem label="Rust">

```rust
let cached = zart::step_or(fetch_remote_config(), Config::default()).await?;
```

</TabItem>
<TabItem label="Python">

```python
cached = await zart.step_or(fetch_remote_config(), default_config)
```

</TabItem>
<TabItem label="TypeScript">

```ts
const cached = yield* Zart.stepOr(fetchRemoteConfig(), defaultConfig);
```

</TabItem>
</Tabs>

### `step_or_else` / `Zart.stepOrElse`

Execute a step, computing a fallback on **business errors only**. Framework-level failures (`RetryExhausted`, `TimedOut`, `DeadlineExceeded`) are **not** passed to the fallback and continue to propagate.

<Tabs syncKey="sdk">
<TabItem label="Rust">

```rust
let payment = zart::step_or_else(
    charge_card(account_id.clone(), data.amount),
    |e: PaymentError| {
        PaymentResult { transaction_id: "fallback".into(), amount: 0.0 }
    },
)
.await?;
```

</TabItem>
<TabItem label="Python">

```python
payment = await zart.step_or_else(
    charge_card(account_id, data.amount),
    lambda err: PaymentResult(transaction_id="fallback", amount=0.0),
)
```

</TabItem>
<TabItem label="TypeScript">

```ts
const payment = yield* Zart.stepOrElse(
  chargeCard(accountId, data.amount),
  (_err) => ({ transactionId: "fallback", amount: 0 }),
);
```

</TabItem>
</Tabs>

## Parallel Execution

### `schedule` and `wait` / `Zart.waitAll`

Register multiple steps for parallel execution without waiting, then collect their results in handle order.

<Tabs syncKey="sdk">
<TabItem label="Rust">

```rust
let h1 = zart::schedule(check_service("auth-api".into()));
let h2 = zart::schedule(check_service("payments".into()));
let h3 = zart::schedule(check_service("users-db".into()));

let results = zart::wait(vec![h1, h2, h3]).await?;
for result in results {
    let svc = result?;  // fail-fast on any step failure
    println!("{}: {}", svc.name, svc.status);
}
```

</TabItem>
<TabItem label="Python">

```python
h1 = zart.schedule(check_service("auth-api"))
h2 = zart.schedule(check_service("payments"))
h3 = zart.schedule(check_service("users-db"))

outcomes = await zart.wait([h1, h2, h3])
for outcome in outcomes:
    svc = outcome.unwrap()
    print(f"{svc.name}: {svc.status}")
```

</TabItem>
<TabItem label="TypeScript">

```ts
const h1 = yield* Zart.schedule(checkService("auth-api"));
const h2 = yield* Zart.schedule(checkService("payments"));
const h3 = yield* Zart.schedule(checkService("users-db"));

const services = yield* Zart.waitAll([h1, h2, h3]);
for (const svc of services) {
  console.log(`${svc.name}: ${svc.status}`);
}
```

</TabItem>
</Tabs>

## Time and Events

### `sleep`

Suspend execution for a duration, resuming at `now + duration`. The `name` must be a stable, unique string within this execution body.

<Tabs syncKey="sdk">
<TabItem label="Rust">

```rust
zart::sleep("warehouse-settle", Duration::from_secs(60)).await?;
```

</TabItem>
<TabItem label="Python">

```python
await zart.sleep("warehouse-settle", "60s")
```

</TabItem>
<TabItem label="TypeScript">

```ts
yield* Zart.sleep("warehouse-settle", "60 seconds");
```

</TabItem>
</Tabs>

### `sleep_until` / `Zart.sleepUntil`

Suspend execution until an absolute UTC timestamp.

<Tabs syncKey="sdk">
<TabItem label="Rust">

```rust
let next_monday = compute_next_monday();
zart::sleep_until("wait-for-monday", next_monday).await?;
```

</TabItem>
<TabItem label="Python">

```python
await zart.sleep_until("wait-for-monday", next_monday)
```

</TabItem>
<TabItem label="TypeScript">

```ts
const nextMonday = new Date("2026-11-23T09:00:00Z");
yield* Zart.sleepUntil("wait-for-monday", nextMonday);
```

</TabItem>
</Tabs>

### `wait_for_event` / `Zart.waitForEvent`

Wait for an external event to be delivered to this execution via `offer_event` / `offerEvent`.

<Tabs syncKey="sdk">
<TabItem label="Rust">

```rust
let decision: ApprovalDecision = zart::wait_for_event(
    "manager-approval",
    Some(Duration::from_secs(86400)),
).await?;
```

</TabItem>
<TabItem label="Python">

```python
decision = await zart.wait_for_event(
    "manager-approval",
    timeout="24h",
    target_type=ApprovalDecision,
)
```

</TabItem>
<TabItem label="TypeScript">

```ts
const ApprovalDecision = Schema.Struct({ approved: Schema.Boolean });
const decision = yield* Zart.waitForEvent("manager-approval", {
  schema: ApprovalDecision,
  timeout: "24 hours",
});
```

</TabItem>
</Tabs>

See [**Steps → wait_for_event**](/docs/concepts/steps/#wait_for_event--external-signals) for the full walkthrough.

## Durable Values

### `capture`

Capture a non-deterministic value durably. On the first run, the function is evaluated and its result is persisted; on replay, the cached value is returned without re-evaluating.

<Tabs syncKey="sdk">
<TabItem label="Rust">

```rust
let started_at = zart::capture!("started-at", chrono::Utc::now());
// On replay: returns the cached DateTime — Utc::now() is never called again.
```

The macro form `zart_capture!` (re-exported as `zart::capture!`) expands to `::zart::capture(name, || expr).await?`.

</TabItem>
<TabItem label="Python">

```python
seed = await zart.capture("random-seed", lambda: str(uuid4()))
```

</TabItem>
<TabItem label="TypeScript">

```ts
const seed = yield* Zart.capture("random-seed", () => randomUUID());
```

</TabItem>
</Tabs>

### `now`

<Tabs syncKey="sdk">

</TabItem>

</TabItem>

## Introspection

### `context`

Returns read-only metadata (`ExecutionInfo`) about the current execution. Accessible from both workflow bodies and step bodies.

<Tabs syncKey="sdk">
<TabItem label="Rust">

```rust
let info = zart::context();
println!("Execution: {}", info.execution_id);
println!("Task:      {}", info.task_name);
println!("Attempt:   {}", info.current_attempt);
println!("Is retry:  {}", info.is_retry());
```

</TabItem>
<TabItem label="Python">

```python
info = zart.context()
print(f"Execution: {info.execution_id}")
print(f"Task:      {info.task_name}")
print(f"Attempt:   {info.current_attempt}")
print(f"Is retry:  {info.is_retry()}")
```

</TabItem>
<TabItem label="TypeScript">

```ts
const info = yield* Zart.context;
console.log("Execution:", info.executionId);
console.log("Task:", info.taskName);
console.log("Attempt:", info.currentAttempt);
console.log("Is retry:", info.isRetry);
```

</TabItem>
</Tabs>

| Rust / Python Field | TypeScript Field | Type | Description |
|---|---|---|---|
| `execution_id` | `executionId` | `String` / `str` / `string` | Unique identifier of this execution |
| `task_name` | `taskName` | `String` / `str` / `string` | Registered name of the handler |
| `data` | `data` | `Value` / `Any` / `unknown` | The original input payload (read-only) |
| `current_attempt` | `currentAttempt` | `usize` / `int` / `number` | 0-indexed retry count |
| `max_retries` | `maxRetries` | `Option<usize>` / `int \| None` / `number \| undefined` | Maximum configured retries |
| `is_retry()` | `isRetry` | `bool` / `boolean` | `current_attempt > 0` |
